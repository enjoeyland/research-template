# ADR (Architecture Decision Record)

이 폴더는 프로젝트의 굵직한 아키텍처/방법론 결정을 기록한다. "왜 이렇게 결정했는지"를
코드나 실험 config만 보고는 알기 어려운 것들 — 예를 들어 알고리즘 선택, 모델 백본 교체,
파이프라인 구조 변경 같은 결정을 남긴다.

## 파일명 규칙

`YYMMDD-adr-주제.md` (예: `261004-adr-hydra-lightning-results-csv.md`)

`docs/`의 다른 문서 파일명 규칙(날짜 접두사)과 통일했다.

## 템플릿

```markdown
# ADR: <결정 제목>

## Status
제안됨 / 승인됨 / 폐기됨 / 대체됨 (날짜)

## Context
왜 이 결정이 필요했는지, 어떤 문제/제약이 있었는지.

## Decision
실제로 어떤 결정을 내렸는지.

## Consequences
이 결정으로 인한 장단점, 트레이드오프, 후속 영향.
```

## 언제 작성하나

되돌리기 어렵거나 프로젝트 방향에 영향이 큰 결정만 기록한다 (예: 알고리즘 선택, 모델 백본 교체,
파이프라인 구조 변경). 실험 config 조정이나 하이퍼파라미터 튜닝처럼 작은 결정은 대상이 아니다.
