# <무엇을 왜 고쳤나 한 줄>

> **상태 (YYYY-MM-DD)**: 고쳤는지, 어떻게 검증했는지, 남은 위험이 있는지 2~3줄.

> 이 폴더는 **코드 수정의 이야기**(증상 → 원인 → 근거 → 수정 → 검증)를 남긴다. 코드 주석에는 이 줄이 왜 이렇게 생겼는지의 불변 조건/함정만
> 1~3줄로 쓰고 길면 이 문서를 가리킨다(`# see docs/implementation/YYMMDD_xxx.md`). 한 줄 요약은 git 커밋 메시지에 둔다.
> 실험 결과(성능 숫자와 해석)는 `../experiments/`에 쓴다.

## 0. 쓰는 기준
조사가 필요했던 버그, 설계에 영향을 주는 변경, 같은 실수가 반복될 수 있는 것만 쓴다. 한 줄로 끝나는 수정은 커밋 메시지로 충분하다.

## 1. 증상
어떻게 발견했나. 실제 오류 메시지/숫자/재현 명령(어떤 config, 어떤 값에서만 나는지).

## 2. 원인
확정한 원인과, **세운 뒤 기각한 가설**(왜 기각했나)을 표로 남긴다. 다음 사람이 같은 가설을 다시 파지 않게 한다.

| 가설 | 확인 방법 | 결과 |
|---|---|---|
| | | ✅ 원인 / ❌ 기각 |

## 3. 근거
원인을 확정한 **측정/재현**(로그, 값, 최소 재현). 추측이 아니라 관찰한 것만.

## 4. 수정
무엇을 어떻게 바꿨나(핵심 diff 요지). 왜 이 방법이고 다른 방법은 왜 안 했나.

## 5. 검증
어떻게 고쳐졌음을 확인했나(테스트 이름, 재현 명령의 전/후). 회귀 테스트를 추가했으면 위치.

## 6. 영향 범위 / 남은 위험
다른 곳에도 같은 문제가 있을 수 있나(예: 원본 프로젝트), 이전 결과가 영향받나, 아직 안 고친 것.

## 7. 반복 방지
같은 실수를 막는 규칙이 있는가. 있으면 `CLAUDE.md`(사용자가 관리, 수정안 제안만)나 폴더 README에 올릴 한 줄을 적는다.
